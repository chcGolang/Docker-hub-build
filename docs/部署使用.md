# 部署使用文档

本仓库构建的多项目 Docker 镜像均发布到 Docker Hub。本文档说明通用约定，并按项目给出具体部署示例。

> **新增项目时**：在本文档末尾追加该项目的部署小节，并在 [README 项目列表](../README.md) 补一行。

## 通用约定

### 镜像命名与 tag

- 镜像：`chcgolang/<项目>`
- tag：`latest` 始终指向最新构建版本；同时存在 `:<版本号>` 的精确版本 tag，例如 `opencode:2.2.2`
- 多架构：镜像同时支持 `linux/amd64` 与 `linux/arm64`，Docker 会自动拉取匹配宿主架构的版本

### 拉取镜像

```bash
docker pull chcgolang/<项目>:latest
```

### 通用部署建议

- 项目工作目录一般挂载到容器内的 `/workspace`
- Web 服务如需对外访问，务必设置鉴权密码（各项目用各自的环境变量，见对应小节）
- 建议将配置与状态目录挂载为数据卷，避免容器重建后数据丢失
- 容器内二进制支持自更新（默认开启）；镜像重建是持久更新路径，见各小节"更新机制"

## opencode

OpenCode AI 编程代理（V2）的 Web 界面镜像，基于 Debian (trixie)。容器内以 `opencode serve` 前台运行，监听 `0.0.0.0:4096`，可通过浏览器访问。

- 镜像：`chcgolang/opencode`
- 端口：`4096`
- 版本：自动取 opencode 官方 V2 最新版本（与官方 `v2/install` 同一版本源）

### 快速部署（docker run）

```bash
docker run -d --name opencode \
  -p 4096:4096 \
  -v "$PWD/workspace:/workspace" \
  -v opencode-config:/root/.config/opencode \
  -v opencode-share:/root/.local/share/opencode \
  -v opencode-state:/root/.local/state/opencode \
  -v opencode-cache:/root/.cache/opencode \
  -e OPENCODE_PASSWORD='你的密码' \
  chcgolang/opencode:latest
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `-p 4096:4096` | 将容器 4096 端口映射到宿主机 |
| `-v "$PWD/workspace:/workspace"` | 挂载宿主机项目目录作为容器工作目录（容器内默认 `/workspace`） |
| `-v opencode-config:/root/.config/opencode` | 持久化 opencode 配置（模型配置、插件等） |
| `-v opencode-share:/root/.local/share/opencode` | 持久化认证凭据、会话数据库（`opencode.db`）与日志（**重建容器前必须保留**，否则会话丢失） |
| `-v opencode-state:/root/.local/state/opencode` | 持久化状态与服务注册信息 |
| `-v opencode-cache:/root/.cache/opencode` | 持久化缓存 |
| `-e OPENCODE_PASSWORD='你的密码'` | 设置 Web 访问鉴权密码（强烈建议启用） |

> V2 鉴权用户名固定为 `opencode`，密码通过 `OPENCODE_PASSWORD` 设置。V1 的 `OPENCODE_SERVER_USERNAME` 已不再支持；`OPENCODE_SERVER_PASSWORD` 仍可作为兼容别名使用。密码的验证与修改见下方「访问与密码」。

### 看门狗参数（自动升级）

镜像内 `watchdog.sh` 默认每小时通过官方 V2 更新接口检查一次最新版本；发现新版本时**立即执行 `opencode upgrade` 并重启** `opencode serve` 进程使新版生效，**不等待空闲**，正在使用的会话会被中断，刷新页面重连即可。opencode 内置自更新替换二进制后，看门狗也会检测到并自动重启。以下环境变量均可选：

| 环境变量 | 默认 | 说明 |
|---------|------|------|
| `OPENCODE_WATCH_POLL_SECONDS` | `30` | `opencode serve` 进程存活检查间隔（秒），崩溃自动拉起 |
| `OPENCODE_WATCH_CHECK_SECONDS` | `3600` | 版本检查与自动升级间隔（秒），启动后立即检查一次 |
| `OPENCODE_UPDATE_API` | `https://opencode.ai/update/api/latest/cli/npm` | 官方 V2 版本接口（与 `v2/install` 同源） |
| `OPENCODE_PORT` | `4096` | `opencode serve` 监听端口（与 `-p` 映射一致） |

### 数据目录

opencode 数据分散在 4 个目录（XDG 规范）：

| 类型 | 容器内路径 | 内容 |
|------|-----------|------|
| 配置 | `/root/.config/opencode` | `opencode.json(c)`、agents、commands、skills、plugins 等 |
| 数据 | `/root/.local/share/opencode` | 认证凭据、会话数据库 `opencode.db`、日志 `log/opencode.log` |
| 状态 | `/root/.local/state/opencode` | 服务注册等运行时状态 |
| 缓存 | `/root/.cache/opencode` | 缓存与受管二进制 |

> **注意**：V2 的会话与项目数据存放在 data 目录的 SQLite 数据库 `opencode.db` 中。更新镜像执行 `docker rm -f opencode` 前，确认 `opencode-share` 卷已挂载且保留，否则所有会话记录会被清空。

### 从 V1 升级到 V2

`latest` tag 已切换到 OpenCode V2，直接 `docker pull chcgolang/opencode:latest` 并重建容器即会升级。升级前请注意：

1. **先备份数据卷**：`docker run --rm -v opencode-share:/data -v "$PWD":/backup alpine tar czf /backup/opencode-share.tgz -C /data .`（state 卷同理）。首次以 V2 启动时会自动把 V1 会话历史迁移进 `opencode.db`，该迁移不可逆。
2. **回滚有限**：仍可运行旧 tag `chcgolang/opencode:1.19.5`，但 V2 已迁移/清理的 V1 会话数据不会自动还原。
3. **配置兼容**：V1 的 `opencode.json(c)`、agents、commands、skills、MCP 配置可继续使用；V1 **插件 API 与 server API 是破坏性变更**，依赖它们的插件/集成需要按 V2 重写。
4. 容器内命令由 `opencode web` 改为 `opencode serve`，对外端口与访问方式不变。

### 访问与密码

浏览器打开 `http://<主机IP>:4096`，使用用户名 `opencode` 和设置的 `OPENCODE_PASSWORD` 登录。

验证密码是否生效：

```bash
docker inspect opencode --format '{{.Config.Env}}' | tr ' ' '\n' | grep OPENCODE_
curl -u 'opencode:你的密码' http://<主机IP>:4096/api/info
# 返回包含 "version":"2.x.x" 的 JSON 即成功；不带凭据应返回 401
```

- **未设置密码**：V2 会随机生成密码并打印到日志，可用 `docker logs opencode | grep 'server password'` 查看，不建议长期这样使用。
- **修改密码**：`OPENCODE_PASSWORD` 只在启动时读取，需删除并重建容器（数据卷保留）：
  ```bash
  docker rm -f opencode
  # 用新密码重新执行上面的 docker run 或 docker compose up -d
  ```
  改密码会让所有已登录的浏览器会话（有效期 30 天）立即失效。
- **安全提示**：Web 鉴权使用 HTTP Basic，密码在 HTTP 下为明文传输。暴露到公网时请在前面部署 HTTPS 反向代理（Caddy/Nginx），并优先只映射反向代理端口。

### docker compose 示例

```yaml
services:
  opencode:
    image: chcgolang/opencode:latest
    container_name: opencode
    ports:
      - "4096:4096"
    environment:
      OPENCODE_PASSWORD: "你的密码"
      # 可选：看门狗参数（自动升级，见"看门狗参数"小节）
      # OPENCODE_WATCH_CHECK_SECONDS: 3600
      # OPENCODE_UPDATE_API: https://opencode.ai/update/api/latest/cli/npm
    volumes:
      - ./workspace:/workspace
      - opencode-config:/root/.config/opencode
      - opencode-share:/root/.local/share/opencode
      - opencode-state:/root/.local/state/opencode
      - opencode-cache:/root/.cache/opencode
    restart: unless-stopped

volumes:
  opencode-config:
  opencode-share:
  opencode-state:
  opencode-cache:
```

### 更新机制

- **容器内自动升级（看门狗）**：看门狗每小时通过官方 V2 更新接口检查最新版本，发现新版本后立即 `opencode upgrade` 并重启 `opencode serve` 进程，无需手动 `docker restart`。不等待空闲，**正在使用的会话会中断，刷新重连即可**；opencode 内置自更新替换二进制后同样会自动重启。
  - 升级失败（网络等）不影响当前运行版本，下一轮检查自动重试。
  - 容器被删除重建后会回到镜像内烧入的版本。
- **镜像重建（持久更新路径）**：CI 每天 UTC 02:00 检测 opencode 官方 V2 新版本，版本变化时重新构建并推送 `latest` + `:<版本号>`。更新步骤：
  ```bash
  docker pull chcgolang/opencode:latest
  docker rm -f opencode
  # 重新执行上方的 docker run 或 docker compose up -d
  ```

### 常见操作

```bash
docker logs opencode          # 查看日志
docker restart opencode       # 重启
docker rm -f opencode         # 删除容器
```

## subconverter

基于官方 `tindy2013/subconverter` 镜像，在入口自动根据**环境变量**改写 `/base/pref.ini`，无需手动编辑或挂载配置文件即可完成常用配置。本质是官方 `subconverter` 的**订阅格式转换服务**：把各种订阅（SS/SSR/V2Ray/Trojan/Clash 等）转换为目标客户端格式。

- 镜像：`chcgolang/subconverter`
- 端口：`25500`
- 版本：自动取 subconverter 官方最新 release

### 快速部署（docker run）

```bash
docker run -d --name subconverter \
  -p 25500:25500 \
  -e SC_API_ACCESS_TOKEN='你的token' \
  -e SC_MANAGED_CONFIG_PREFIX='http://你的域名:25500' \
  -e SC_DEFAULT_URL='https://你的订阅地址' \
  -e SC_PORT=25500 \
  chcgolang/subconverter:latest
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `-p 25500:25500` | 将容器 25500 端口映射到宿主机 |
| `-v "$PWD/base:/base"` | 可选，挂载配置目录持久化 `pref.ini` 等文件 |
| `-e SC_*` | 通过环境变量覆盖 `pref.ini` 配置（见下表） |
| `-e API_MODE` / `MANAGED_PREFIX` / `API_TOKEN` | subconverter 原生支持的环境变量，见下方说明 |

### 环境变量（SC_* 白名单）

容器入口会根据以下环境变量自动改写 `/base/pref.ini`（非空才生效，均在 `pref.ini` 对应 section 中覆盖同名键）：

| 环境变量 | 对应 pref.ini | 默认值 |
|---------|--------------|--------|
| `SC_API_MODE` | `[common] api_mode` | `false` |
| `SC_API_ACCESS_TOKEN` | `[common] api_access_token` | `password` |
| `SC_DEFAULT_URL` | `[common] default_url` | 空 |
| `SC_INSERT_URL` | `[common] insert_url` | 空 |
| `SC_ENABLE_INSERT` | `[common] enable_insert` | `true` |
| `SC_EXCLUDE_REMARKS` | `[common] exclude_remarks` | `(到期\|剩余流量\|...)` |
| `SC_INCLUDE_REMARKS` | `[common] include_remarks` | 空 |
| `SC_PROXY_CONFIG` | `[common] proxy_config` | `SYSTEM` |
| `SC_PROXY_RULESET` | `[common] proxy_ruleset` | `SYSTEM` |
| `SC_PROXY_SUBSCRIPTION` | `[common] proxy_subscription` | `NONE` |
| `SC_RELOAD_CONF_ON_REQUEST` | `[common] reload_conf_on_request` | `false` |
| `SC_MANAGED_CONFIG_PREFIX` | `[managed_config] managed_config_prefix` | `http://127.0.0.1:25500` |
| `SC_CONFIG_UPDATE_INTERVAL` | `[managed_config] config_update_interval` | `86400` |
| `SC_CONFIG_UPDATE_STRICT` | `[managed_config] config_update_strict` | `false` |
| `SC_LISTEN` | `[server] listen` | `0.0.0.0` |
| `SC_PORT` | `[server] port` | `25500` |
| `SC_LOG_LEVEL` | `[advanced] log_level` | `info` |
| `SC_ENABLE_CACHE` | `[advanced] enable_cache` | `false` |
| `SC_CACHE_SUBSCRIPTION` | `[advanced] cache_subscription` | `60` |
| `SC_CLASH_HTTP_PORT` | `[template] clash.http_port` | `7890` |
| `SC_CLASH_SOCKS_PORT` | `[template] clash.socks_port` | `7891` |
| `SC_CLASH_ALLOW_LAN` | `[template] clash.allow_lan` | `true` |
| `SC_CLASH_EXTERNAL_CONTROLLER` | `[template] clash.external_controller` | `127.0.0.1:9090` |
| `SC_SINGBOX_MIXED_PORT` | `[template] singbox.mixed_port` | `2080` |
| `SC_SINGBOX_ALLOW_LAN` | `[template] singbox.allow_lan` | `true` |
| `SC_ADD_EMOJI` | `[emojis] add_emoji` | `true` |
| `SC_REMOVE_OLD_EMOJI` | `[emojis] remove_old_emoji` | `true` |

> `SC_MANAGED_CONFIG_PREFIX` 是托管配置的地址前缀，Surge/Surfboard 生成的 `#!MANAGED-CONFIG` 及 `/getruleset`、`/qx-rewrite`、`/qx-script` 地址都会拼接此前缀。默认 `127.0.0.1` 会导致客户端无法访问，公网部署务必改为客户端可达的 `http://域名:端口`。

### 原生环境变量

subconverter 自身在启动时直接读取以下环境变量（`main.cpp`），无需写入 `pref.ini`，本镜像同样支持：

| 环境变量 | 作用 |
|---------|------|
| `API_MODE` | 覆盖 `[common] api_mode` |
| `MANAGED_PREFIX` | 覆盖 `[managed_config] managed_config_prefix` |
| `API_TOKEN` | 覆盖 `[common] api_access_token` |

> 三者优先级高于 `pref.ini`。若无需 `SC_*` 白名单之外的更多自定义配置，直接用这三个原生变量更简单。

### 配置优先级与数据卷

- subconverter 原生配置优先级为 `pref.toml` > `pref.yml` > `pref.ini`。本镜像入口会**确保 `pref.ini` 存在**并应用 `SC_*` 覆盖；如果你挂载了自己的 `pref.toml` 或 `pref.yml`，入口将跳过 `SC_*` 覆盖（日志会提示），直接使用你挂载的配置。
- 配置目录：`/base`（含 `pref.ini`、规则、snippets 等）。如需持久化自定义配置，挂载 `-v "$PWD/base:/base"`，但注意挂载后容器内初始化的规则文件可能被覆盖，建议仅挂载需要的单个文件（如 `pref.ini`）。
- 无认证/状态/缓存持久化目录需求。

### 访问接口

转换接口（`url` 参数需 URL 编码）：

```text
http://<主机IP>:25500/sub?target=clash&url=你的订阅地址(URL编码)
http://<主机IP>:25500/version   # 检查运行状态
```

常用 target：`clash`、`clashr`、`surge`、`quanx`、`loon`、`ss`、`ssr`、`v2ray`、`trojan`、`singbox` 等。API 变更配置需提供 `token`（即 `SC_API_ACCESS_TOKEN` 值）：

```bash
curl -F "data=@newpref.ini" "http://<主机IP>:25500/updateconf?type=form&token=你的token"
```


### 更新与回滚

- **镜像重建（持久更新路径）**：CI 每天 UTC 02:00 检测 subconverter 官方新版本，版本变化时重新构建并推送 `latest` + `:<版本号>`。更新步骤：
  ```bash
  docker pull chcgolang/subconverter:latest
  docker rm -f subconverter
  # 重新执行上方的 docker run 或 docker compose up -d
  ```
- **回滚**：指定旧版本 tag 启动，例如 `chcgolang/subconverter:0.9.0`。


## workbuddy-gateway

腾讯 CodeBuddy 账号池 + OpenAI / Anthropic 兼容反代网关（Go 单二进制），可选网页控制台。国内站与国际站账号可混挂在同一账号池轮询。

- 镜像：`chcgolang/workbuddy-gateway`
- 端口：`8317`（模型 API）、`8316`（网页控制台，镜像默认启用 `-webui`）
- 版本：自动取上游最新 Release（tag 去掉 `v` 前缀）
- 数据目录：容器内 `/data`（配置、凭据、日志、统计、缓存全部在此）

### 快速部署（docker run）

```bash
mkdir -p "$PWD/workbuddy"

docker run -d --name workbuddy-gateway \
  -p 8317:8317 \
  -p 8316:8316 \
  -v "$PWD/workbuddy:/data" \
  -e TZ=Asia/Shanghai \
  --restart unless-stopped \
  chcgolang/workbuddy-gateway:latest
```

首次启动会在 `/data` 生成默认 `config.json`。容器默认执行：

```text
workbuddy-gateway serve -addr 0.0.0.0 -webui
```

> 必须使用 `-addr 0.0.0.0`，否则容器内只监听 `127.0.0.1`，端口映射无法访问。

### 首次配置（管理 Key 与模型 API Key）

编辑宿主机 `./workbuddy/config.json` 的 `gateway` 段（文件由容器以 root 创建，可能需要 `sudo`）：

```json
{
  "gateway": {
    "apiPort": 8317,
    "webPort": 8316,
    "adminKey": "请替换为32位随机字符串",
    "apiKeyEnabled": true,
    "apiKey": "sk-请替换"
  }
}
```

- `adminKey`：网页控制台登录 Key，建议 32 位随机字符串；保存后约 1 秒热生效，无需重启
- `apiKeyEnabled` / `apiKey`：模型 API 鉴权；对外开放时务必开启
- 修改 `apiPort` / `webPort` 后同样热切换，注意同步调整 `-p` 映射

生成随机 Key：

```bash
python3 -c 'import secrets; print(secrets.token_hex(16))'
```

### 添加账号

方式一：网页控制台（推荐）

浏览器打开 `http://<主机IP>:8316/ui/`，用 `adminKey` 登录，在「账号池」→「添加账号」选择国内站或国际站，按提示扫码或打开登录链接。

方式二：容器内命令行

```bash
# 国内站：微信 / 企业微信扫码
docker exec -it workbuddy-gateway workbuddy-gateway login

# 国际站：浏览器内完成登录
docker exec -it workbuddy-gateway workbuddy-gateway login -intl

# 指定凭据文件名（多账号）
docker exec -it workbuddy-gateway workbuddy-gateway login -auth workbuddy2.json

# 查看账号池状态
docker exec -it workbuddy-gateway workbuddy-gateway status
```

凭据保存在 `/data/workbuddy*.json`，新增 / 更新 / 删除默认 5 秒内热加载，无需重启。

> 网页控制台的「一键生成管理 Key」只允许容器内回环来源。通过 Docker 端口映射访问时来源不是 `127.0.0.1`，请先按上面的方式手动写入 `adminKey`。

### 参数说明

| 参数 | 说明 |
|---|---|
| `-p 8317:8317` | 模型 API 端口 |
| `-p 8316:8316` | 网页控制台端口（镜像默认 `-webui` 启用） |
| `-v "$PWD/workbuddy:/data"` | 持久化配置、凭据、日志、统计与缓存 |
| `-e TZ=Asia/Shanghai` | 容器时区，影响日志日期与统计展示；项目签到逻辑本身固定 UTC+8 |

### 数据目录

| 容器内路径 | 内容 |
|---|---|
| `/data/config.json` | 主配置（端口、管理 Key、模型 API Key、日志、并发、身份替换等） |
| `/data/workbuddy*.json` | 账号凭据（含 Access / Refresh Token，**敏感**） |
| `/data/logs/` | 普通日志、调试日志、部署与前端审计日志 |
| `/data/stats.json` | 用量与性能统计 |
| `/data/checkin-state.json` | 国内站每日签到状态 |
| `/data/wb-models-cache.json` | 模型目录缓存 |
| `/data/workbuddy-status.json` | 供 `monitor` 读取的运行时状态快照 |

> 只需挂载 `/data` 一个卷。删除容器不会删除该目录；删除它等于清空账号与统计。

### 可选启动参数

镜像默认命令可通过覆盖 `CMD` 调整，例如开启后台价格探测（会发起真实生成请求，可能消耗积分）：

```bash
docker run -d --name workbuddy-gateway \
  -p 8317:8317 \
  -p 8316:8316 \
  -v "$PWD/workbuddy:/data" \
  -e TZ=Asia/Shanghai \
  --restart unless-stopped \
  chcgolang/workbuddy-gateway:latest \
  serve -addr 0.0.0.0 -webui -allow-price-probes
```

常用参数（详见上游使用手册）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-addr` | `0.0.0.0`（镜像内） | 监听地址 |
| `-port` | `8317` | 模型 API 端口，显式传入时覆盖 `config.json` |
| `-webui` | 镜像默认开启 | 启用网页控制台 |
| `-auth` / `-auth-dir` | 自动发现 `/data/workbuddy*.json` | 凭据文件或目录 |
| `-proxy` | 空 | 上游代理 |
| `-reload-interval` | `5` | 凭据热加载间隔（秒），`0` 关闭 |
| `-allow-price-probes` | 关闭 | 后台价格探测，可能消耗积分 |

### 更新与回滚

- **更新**：CI 每天 UTC 02:00 检测上游新 Release，版本变化时重新构建并推送 `latest` + `:<版本号>`：
  ```bash
  docker pull chcgolang/workbuddy-gateway:latest
  docker rm -f workbuddy-gateway
  # 重新执行 docker run 或 docker compose up -d，/data 数据保留
  ```
- **回滚**：指定旧版本 tag，例如 `chcgolang/workbuddy-gateway:1.14.43`。
- **配置兼容警告**：旧版本二进制遇到新版 `config.json` 中不认识的字段会拒绝启动。升级前先备份 `./workbuddy/config.json`；回滚镜像时若启动失败，需要同时恢复对应旧配置。

备份示例：

```bash
tar czf workbuddy-backup-$(date +%F).tgz -C "$PWD" workbuddy
```

### 安全提示

- `workbuddy*.json` 含真实访问凭据，`config.json` 含管理 Key 与 API Key，切勿公开分享或提交到 Git。
- 对外开放时务必开启 `gateway.apiKeyEnabled` 并设置随机 `gateway.adminKey`。
- 网页控制台与 API 默认都是 HTTP 明文，暴露公网时建议放在 HTTPS 反向代理之后，并且只映射必要端口。
- 不再使用的账号，删除 `/data/workbuddy*.json` 并在 CodeBuddy 控制台撤销授权。
